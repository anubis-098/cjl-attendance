# SQL storage

แอปเริ่มต้นว่าง ไม่ seed พนักงาน กะ หรือสแกนตัวอย่าง และไม่โหลดข้อมูล `shiftly-v1` จาก localStorage อีกต่อไป การเลือกตัวกรองยังเก็บใน sessionStorage ได้

## ฐานข้อมูล

PostgreSQL 17 หนึ่ง service และสองฐานข้อมูลจริง:

- `employee_db.employee_master`: รหัสพนักงาน, แถวต้นทาง, ข้อมูลทุก Header ของ Master, กะที่ตรวจแล้ว และข้อสังเกต
- `employee_db.employee_file`: SQL view ที่ใช้ชื่อคอลัมน์ตรงกับไฟล์ รวม `Satatus`, `End ` และ `Status` แยกกัน
- `employee_db.workspace`: ตารางกะรายวัน, ผลตรวจสอบ, audit, revision และตัวชี้ชุดสแกนปัจจุบัน
- `fingerprint_db.import_batches` และ `fingerprint_db.fingerprint_logs`: ชุดนำเข้าและสแกนที่ไม่ซ้ำ ดัชนีตามรหัส/เวลา
- `fingerprint_db.fingerprint_file`: view รหัสพนักงาน / ปี/เดือน/วัน (YYYYMMDD) / เวลาสแกนนิ้ว (HHmm) ตามชื่อที่ผู้ใช้ยืนยัน ไฟล์ TXT ไม่มี Header จริง

SQL เริ่มต้นอยู่ที่ `sql/001-databases.sql` ข้อมูลเก็บใน Docker volume `cj_sql_data` การ restart/rebuild ไม่ล้างข้อมูล ไม่เปิดพอร์ต PostgreSQL ของฐานจริงออกจาก Docker

## Import

1. `/employees`: Import Master Name list.xlsx (เลือกชีต Master Name) หรือ CSV/XLS ที่มี Header เดียวกัน เก็บทุกคอลัมน์ รวมแถวที่เวลากะมีข้อขัดแย้งเพื่อให้ตรวจได้ ส่วนแถวที่ใช้คำนวณไม่ได้มีคำอธิบาย
2. `/fingerprints`: Import TXT `รหัส<TAB>YYYYMMDD<TAB>HHmm` ตรวจรูปแบบ/วันที่ก่อนเขียน และตัดรายการซ้ำภายในชุดไฟล์
3. `/attendance`: ดึงทั้งสองฐานมาเทียบตามรหัสแบบตรงตัว ถ้ายังไม่มีตารางรายวัน จะสร้างรายการเฉพาะวันที่มีสแกนอ้างอิงกะ Master รวมกะข้ามคืน ไม่เดาวันหยุด การลา หรือคำขอ OT
4. นำเข้า CJ สามไฟล์ในหน้า Attendance ได้เหมือนเดิม เพื่อใช้รหัสรายวันจากรายงาน Agency แทนกะหลัก; รูปแบบ CSV มาตรฐานที่มีคำขอ OT รายวันยังรองรับ

Import พนักงานแทนที่ชุดพนักงานและล้างตารางกะ/ผลตรวจสอบให้เทียบใหม่ โดยคงสแกนไว้ Import สแกนแทนที่ชุดสแกนที่ใช้เทียบและเปิดผลตรวจสอบใหม่ โดยคง Master และแผนรายวันไว้ การนำเข้าสามไฟล์แทนที่ทั้งชุดกะและสแกน

หลัง trim รหัส Master ตัวอย่างเหลือ 350 รหัส พบรหัสซ้ำ 3 รหัส (รวมรหัสที่มีช่องว่างท้าย) เก็บแถวแรกและต้นฉบับแถวซ้ำใน `source_data.__duplicate_rows` พร้อมหมายเหตุ ไม่ทิ้งข้อมูลต้นฉบับ ถ้าข้อมูลกะขัดแย้งจะไม่ใช้รหัสนั้นคำนวณ

ชุดสแกนใหม่ถูกเตรียมใน fingerprint_db ก่อน แล้วจึงสลับตัวชี้ใน transaction ของ employee_db ผู้อ่านจึงยังเห็นชุดเก่าจนกว่าทั้งการอ่านไฟล์และการเขียนจะสำเร็จ ชุดเก่ายังคงอยู่เพื่อไม่ให้การอ่านที่เริ่มก่อน Import ขาดข้อมูล การสำรองต้องสำรองทั้งสองฐาน

ผลตรวจสอบเขียนผ่าน API มี revision ป้องกันการบันทึกทับข้อมูลที่เปลี่ยนไปแล้ว และตรวจเงื่อนไขรับรองอีกครั้งที่ server ไม่ใช้ผลในเบราว์เซอร์เป็นหลักฐานการบันทึกสำเร็จ

## เริ่มระบบ

```sh
docker compose up --build -d
```

เปิด http://localhost:3000 กำหนด `POSTGRES_PASSWORD` ใน `.env` ได้ ค่าที่ระบุใน Compose เป็นค่าเริ่มต้นสำหรับเครื่องพัฒนา การเปลี่ยนค่าภายหลังสร้าง volume ต้องเปลี่ยนรหัสผ่าน role ใน PostgreSQL ให้ตรงกันด้วย

สำหรับ `npm run dev` ต้องมีฐานข้อมูลที่สร้าง schema แล้ว และตั้ง `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD` ส่วนชื่อฐานเปลี่ยนได้ด้วย `EMPLOYEE_DB` และ `FINGERPRINT_DB`

## การทดสอบ

```sh
npm test
docker compose -p cj-attendance-test -f compose.test.yaml up -d
npx playwright test
docker compose -p cj-attendance-test -f compose.test.yaml stop
```

ชุดทดสอบใช้เว็บ 3001 และ PostgreSQL 5433 (localhost เท่านั้น) มี volume แยก และ reset เฉพาะชุดทดสอบก่อน/หลังแต่ละกรณี จึงไม่ใส่ข้อมูลตัวอย่างในฐานจริงพอร์ต 3000

## ขอบเขต

ยังไม่มีระบบ login/RBAC ผู้ใช้งานที่เข้าถึงเว็บได้สามารถ Import และตรวจสอบข้อมูลร่วมกันได้ ส่วน audit ยังไม่ผูกกับตัวตนผู้ใช้จริง ยังไม่เพิ่มการคำนวณเงินเดือนหรือสิทธิค่าจ้างวันลา
