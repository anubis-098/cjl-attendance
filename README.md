# CJ Agent — Agency Attendance & OT

หน้า Employee calendar มีโหมด “เปลี่ยนกะ” เลือกวันที่ในเดือนเดียวกันได้หลายวัน เลือกต้นแบบจากกะในระบบหรือกำหนด M/D/A/N กับเวลาเริ่ม–สิ้นสุดเอง ระบุเหตุผลก่อนยืนยัน และเลือก “คืนค่ากะเดิม” เพื่อลบข้อยกเว้นรายวัน ข้อมูลอยู่ใน SQL `employee_db.workspace.data.shiftOverrides` พร้อม Audit log ไม่แก้ Master/สแกนดิบ ไม่เปลี่ยนรหัสวันหยุด/ลา และคงอยู่หลังนำเข้าไฟล์ใหม่ วันที่แก้จะล้างเวลาเข้า–ออกที่แก้ด้วยมือเพื่อจับสแกนใหม่ วันนั้นกับวันข้างเคียงจะเปิดตรวจสอบใหม่ โดยเก็บค่าก่อนหน้าใน Audit ป้องกันกะใหม่ทับช่วงทำงานข้างเคียง และแบ่งขอบเขตจับสแกนตามกะจริงของแต่ละวัน

ชื่อแผนกปรับเป็นมาตรฐานเมื่ออ่านข้อมูลเดิมและนำเข้าใหม่: `Frozen / FROZEN / Frozen CDC → Frozen`, `Dry / Dry Food / Dryfood → Dry`, `Seafood / Saefood → Seafood`, `FD-FT / FD/FT → FD-FT` ตัดช่องว่างเกินและไม่แยกตัวพิมพ์ใหญ่เล็กสำหรับชื่อเหล่านี้ ไม่รวม Inventory Frozen หรือ Asset Dry เข้ากลุ่ม ข้อมูลต้นฉบับยังอยู่ใน `source_data` และดูได้จาก tooltip ในหน้าพนักงาน ชื่อแผนกที่ต่างกันเพียง alias ไม่ทำให้รหัสพนักงานซ้ำถูกตัดออกว่าเป็นกะขัดแย้ง แต่ความขัดแย้งของเวลาหรือข้อมูลอื่นยังต้องตรวจสอบ

หน้า “คำนวณเงินโอที” (`/payroll`) ตั้งค่าบนเว็บได้โดยไม่ต้องอัปโหลด Excel ค่าจ้าง Agency เริ่มต้น 385.56 บาท/วัน สูตร OT = ค่าจ้าง ÷ 8 × ตัวคูณ ปัดอัตรา 2 ตำแหน่ง มีค่าความคาว Seafood 12.36 ค่าเย็น Frozen 51.50 และค่ากะ M/A/N 20.60/41.20/72.10 บาทต่อวัน ปรับเงินและประเภทเบี้ยเลี้ยงแต่ละแผนกได้ กะ D ไม่มีค่ากะ เบี้ยเลี้ยงจ่ายเฉพาะวันปกติที่สแกนครบ ไม่จ่ายวันหยุด/ลา/ขาดงาน เก็บอัตราใน SQL แยกเดือนจ่ายพร้อม Audit log รองรับรอบ 26–25 หรือเดือนปฏิทิน แยกยืนยันแล้ว/รอยืนยัน มีรายละเอียดรายวันและ CSV ดู [รายละเอียดการคำนวณ](docs/payroll-analysis.md)

OT ต้องครบอย่างน้อย 1 ชั่วโมงต่ออัตราจึงนับได้ (0.5 → 0, 0.9 → 0, 1.0 → 1.0) หลังจากนั้นปัดลงทุกครึ่งชั่วโมง กะที่สแกนไม่ครบแสดงเครื่องหมาย ! บนแถบใน Attendance และปฏิทินรายเดือน

หน้า Employee calendar มีปุ่ม “กำหนดวันหยุด” เลือก H/H8/PH/PH8 แล้วเลือกช่องวันที่หรือวันประจำสัปดาห์ในเดือนนั้นก่อนยืนยัน เก็บข้อมูลใน `employee_db.employee_holidays` แยกจากสแกนนิ้วและตารางนำเข้า สามารถคืนค่าตารางเดิมได้ การเปลี่ยนรหัสจะเปิดผลรับรองของวันที่แก้ให้ตรวจสอบใหม่และบันทึก Audit log

สำหรับฐานข้อมูลที่สร้างก่อนเพิ่มฟังก์ชันนี้ รัน migration ครั้งเดียวโดยไม่ลบ volume:
```powershell
Get-Content sql/003-employee-holidays.sql | docker compose exec -T database psql -U cj_app -d employee_db -v ON_ERROR_STOP=1
```

คลิกชื่อพนักงานจาก Attendance, รายงาน หรือข้อมูลพนักงาน เพื่อเปิด `/employees/[id]/calendar` เป็นปฏิทินรายเดือน วันหยุด H/H8/PH/PH8 ใช้พื้นแดงพาสเทลและลายทแยงสีดำตามตารางกะที่นำเข้า วันที่ไม่มีข้อมูลไม่ถูกเดาเป็นวันหยุด กะข้ามวันแสดงตามสัดส่วน 24 ชั่วโมงและคลิกตรวจสอบรายละเอียดได้

OT ปัดลงเป็นช่วงละ 0.5 ชั่วโมงแยกตามตัวคูณ เช่น 1.9 → 1.5 และ 3.1 → 3.0 โดยเก็บเวลาสแกนเดิมและไม่ปัดชั่วโมงงานปกติ รับรองจากเวลาทำงานจริงโดยไม่ต้องมีคำขอ OT รายวัน ก่อนยืนยันแสดง “ยังไม่ได้ยืนยันโอที” หลังยืนยันจึงรวมในยอด OT ยืนยันแล้ว

เว็บแอป Next.js / React / TypeScript เชื่อม PostgreSQL สองฐาน (`employee_db`, `fingerprint_db`) เริ่มต้นว่าง ไม่มี Mock data ในฐานใช้งานจริง รายละเอียด schema, Import และชุดทดสอบอยู่ใน [SQL storage](docs/sql-storage.md)

## ติดตั้งบน Ubuntu Server

Repository นี้มีเฉพาะเว็บ Attendance ส่วนโปรแกรม Client อยู่ที่ [Finger Service](https://github.com/anubis-098/finger_service)

ติดตั้ง Git, Docker Engine และ Compose plugin ตาม [คู่มือ Docker สำหรับ Ubuntu](https://docs.docker.com/engine/install/ubuntu/) ก่อน จากนั้น:

```bash
git clone https://github.com/anubis-098/cjl-attendance.git
cd cjl-attendance
cp .env.example .env
nano .env
# ตั้ง POSTGRES_PASSWORD ก่อนเปิดระบบครั้งแรก
sudo docker compose up -d --build
sudo docker compose exec web node scripts/bootstrap-accounts.mjs
```

คำสั่งสุดท้ายใช้เฉพาะฐานข้อมูลใหม่ที่ยังไม่มีบัญชี จะแสดงชื่อบัญชีและรหัสผ่านสุ่มสำหรับเข้าสู่ระบบ เก็บไว้เฉพาะผู้ดูแล เปิดเว็บที่ `http://SERVER_IP:3000` โดยอนุญาตพอร์ตตามเครือข่ายที่ใช้งาน เว็บไม่ต้องใช้ Wine หรือหน้าจอ Xfce

อัปเดตในโฟลเดอร์เดิม:

```bash
git pull --ff-only
sudo docker compose up -d --build
sudo docker compose ps
```

ข้อมูล SQL อยู่ใน Docker volume ไม่ติดมากับ Git เครื่องใหม่เริ่มฐานข้อมูลว่าง หากย้ายข้อมูลเดิมต้องสำรองและกู้คืนทั้ง `employee_db` และ `fingerprint_db` แยกต่างหาก ห้ามใช้ `docker compose down -v` หากต้องการเก็บข้อมูลเดิม และตรวจ migration ในเอกสารก่อนอัปเดตฐานข้อมูลรุ่นเก่า

ไฟล์ `examples/` และรายงานวิเคราะห์ข้อมูลภายในไม่เผยแพร่ใน repository การทดสอบบางรายการที่อ่าน Excel/TXT จริงต้องมีไฟล์ตัวอย่างภายในเพิ่มเติม

## การใช้งาน

- `/attendance`: ตารางกะและนำเข้าข้อมูล (หน้า `/` จะพาเข้าหน้านี้)
- `/employees`: ฐานข้อมูลพนักงาน หัวตารางตรงกับ Master Name และ Import แยกได้
- `/fingerprints`: ฐานข้อมูลเวลาสแกนนิ้ว หัวตาราง รหัส / วันที่ / เวลาสแกน และ Import TXT แยกได้
- `/approvals`: รายการรออนุมัติ ตรวจสอบรายรายการ หรือเลือกยืนยันหลายรายการ
- `/audit-log`: ค้นหาประวัติด้วยรหัส/ผู้ดำเนินการ/เหตุผล และวันที่ทำงาน พร้อมส่งออก CSV
- การ์ดสรุปลิงก์ไป `/employees`, `/normal-hours`, `/overtime` และ `/approvals` โดยใช้ช่วงเวลาและตัวกรองร่วมกัน ตัวกรองเก็บใน sessionStorage เพื่อคงค่าเมื่อรีเฟรช
- แต่ละหน้าเป็น Next.js App Router route จริง รองรับเปิดลิงก์ตรง รีเฟรช และปุ่มย้อนกลับของเบราว์เซอร์ ข้อมูลและการอนุมัติใช้ workspace ร่วมกัน

- ตารางรายสัปดาห์ / 2 สัปดาห์ / เดือน เลือกวันที่และกรอง Agency แผนก กะ สถานะ หรือชื่อพนักงาน
- กะข้ามคืนแสดงเป็นแถบเดียวเชื่อมคอลัมน์วันเข้าและวันออก แยกแถวเมื่อกะต่อเนื่องกัน และแสดงส่วนที่ต่อจาก/ไปช่วงก่อนหน้าหรือถัดไป การเลือกวัน ยอดรวม และ CSV ยังยึดวันเริ่มกะเพื่อไม่ให้นับซ้ำ
- เลือกพนักงานหรือคอลัมน์วันแล้วกดยืนยันที่เลือก การยืนยันถือเป็นการรับรองผลงาน รายการสแกนไม่ครบและ OT ที่ไม่ได้ขอจะถูกข้าม
- คลิกกะเพื่อดูข้อมูลดิบ แก้ไขเวลา ระบุเหตุผล/ผลงาน และเปิด Supervisor sign-off
- รายการที่รับรองแล้วถูกล็อก ต้องปิดการรับรองก่อนแก้ไข ทุกการบันทึกและอนุมัติมีประวัติผู้ดำเนินการ เวลา เหตุผล และข้อมูลก่อน/หลัง
- ส่งออก CSV ตามตัวกรอง นำเข้า CSV/XLSX/XLS พร้อมตรวจสอบข้อมูลก่อนแทนที่ชุดเดิม ดาวน์โหลดตัวอย่างทั้งสองไฟล์ได้ในหน้าต่างนำเข้า

## รูปแบบนำเข้า

รองรับไฟล์จริง CJ แบบสามไฟล์: Master Name list.xlsx + Fingerprint TXT + CDC Agency Attendance พร้อมตรวจผลก่อนยืนยัน อ่าน [ผลวิเคราะห์และข้อจำกัด](docs/examples-analysis.md) โค้ดที่ยังไม่ยืนยันจะถูกแยกไว้ในรายงานตรวจสอบ และ OT รวมงวดไม่ถูกใช้แทนคำขอรายวัน

Master: `emp_id,emp_name,department,date,shift_code,shift_start,shift_end,requested_ot_hrs,ot_task_target` และคอลัมน์เสริม `agency,device_emp_id`

Punch: `device_emp_id,punch_timestamp,punch_type` (`IN/OUT/UNKNOWN` หรือ `CHECK_IN/CHECK_OUT`)

ใช้วันที่แบบข้อความ `YYYY-MM-DD`, เวลา `HH:mm`, timestamp `YYYY-MM-DD HH:mm:ss` และเก็บรหัสเป็นข้อความเพื่อรักษาเลขศูนย์นำหน้า หากรหัสเครื่องต่างจากรหัสพนักงานต้องระบุ `device_emp_id` ใน Master ระบบไม่เดาจับคู่จากท้ายรหัส รองรับหนึ่งกะต่อพนักงานต่อวัน

## กฎคำนวณและขอบเขต

- เวลา Asia/Bangkok; แบ่งช่วงสแกนของกะหลักประจำวันตรงกึ่งกลางระหว่างสิ้นสุดกะก่อนหน้าและเริ่มกะถัดไป ใช้ขอบเขตเดียวกันทั้งจัดวันและจับคู่ ไม่ให้ช่วงประจำวันซ้อนกัน เช่นกะ 20:00–05:00 มีช่วงรับสแกนตั้งแต่ 12:30 วันเริ่มกะ ถึงก่อน 12:30 วันถัดไป เวลาเข้าสแกนแรกในช่วงนี้จนถึงหลังเริ่มกะ 120 นาที; เกิน 5 นาทีถือว่าสาย
- เลือกสแกนเข้าแรกและสแกนออกสุดท้ายตั้งแต่สิ้นสุดกะภายในช่วงของกะนั้น รองรับกะข้ามคืน สแกนออกก่อนสิ้นสุดกะหรืออยู่นอกช่วงจับคู่ยังต้องตรวจสอบและปรับด้วยมือ
- กะปกติ 9 ชั่วโมง หักพัก 1 ชั่วโมง = สุทธิ 8 ชั่วโมง OT ก่อนเริ่มกะและหลังเลิกกะใช้ x1.5 (วันปกติ/H/H8) หรือ x3.0 (PH/PH8) ก่อนและหลังกะแยกกันใช้ขั้นต่ำ 1 ชั่วโมงและปัดลงครึ่งชั่วโมงก่อนรวมตามตัวคูณ OT ก่อนกะไม่หักพัก เลือก Checkbox หักพัก OT หลังกะ 30 นาทีรายคน/กะได้เมื่อ OT หลังกะหลังปัดลงก่อนหักพักเกิน 3 ชั่วโมง ค่าเริ่มต้นไม่หัก การยืนยันเก่าที่เวลาจับคู่หรือยอด OT เปลี่ยนต้องยืนยันใหม่ รุ่นกฎบันทึกใน review.otRulesVersion พร้อม Audit ของการยืนยัน
- `PH` วันหยุดประจำปี / `PH8` มาทำงานวันประเพณี: ชั่วโมงในกะหักพัก 1 ชั่วโมงคิด x1.0 และหลังเลิกกะ x3.0 รองรับข้อความ `PH 8` ด้วย
- `H` วันหยุดประจำสัปดาห์ / `H8` วันหยุดประจำสัปดาห์แต่มาทำงาน: ในกะ 9 ชั่วโมงหักพัก 1 ชั่วโมงเป็นเวลาปกติ 8 ชั่วโมง เฉพาะหลังเลิกกะ OT x1.5
- `1` วันทำงานปกติ; `M` กะเช้า, `D` กะเช้าไม่ได้ค่ากะ, `A` กะบ่าย, `N` กะดึก เวลาจริงอ้างอิง Master ไม่เดาจากรหัสกะ ค่ากะรายวันใช้รหัส M/A/N/D โดยรหัสวัน `1` อ้างอิงกะหลักจาก Master
- `WOP` ลากิจไม่รับค่าจ้าง, `PL` ลากิจ, `SL` ลาป่วย, `AB` ขาดงาน, `R` ลาออก ไม่สร้างชั่วโมงทำงาน/OT ถ้ามีสแกนจะแจ้งข้อมูลขัดแย้ง ไม่คิดเป็นสแกนขาด และไม่ได้คำนวณสิทธิค่าจ้างวันลา
- ย้ายรหัสเดิม OFF-M/OFF-D เป็น H และ OFF-H เป็น PH โดยอัตโนมัติ คงข้อมูลและประวัติไว้
- `OFF` เดิมที่มีการทำงานยังรอยืนยันประเภทวันหยุด ไม่เดาว่าเป็น OFF-M, OFF-D หรือ OFF-H ส่วน x2.0 ยังคงเป็นคอลัมน์รายงานที่รองรับ แต่ยังไม่มีกฎใดจัดชั่วโมงเข้าอัตรานี้
- รายงาน OT/รายละเอียด/CSV แยกชั่วโมง x1.0, x1.5, x2.0, x3.0 หลังปัดลง ก่อนคูณอัตรา รับรองตามจริงโดยไม่จำกัดยอดตามคำขอเดิม
- วันหยุดที่ไม่มี log/เวลาแก้ไข ไม่ถือว่าสแกนขาด ถ้ามี log เพียงด้านเดียวต้องตรวจสอบ
- การย้ายจากกฎเดิมจะคงข้อมูลและประวัติไว้ แต่เปิดรายการที่รับรองแล้วให้ตรวจสอบใหม่ พร้อม audit อัตโนมัติ เพื่อไม่ใช้การรับรองเดิมกับยอดคำนวณใหม่
- ขาดสแกนเข้าหรือออกไม่สร้างชั่วโมงจ่าย
- OT x1.5 + x3.0 ตั้งแต่ 3 ชั่วโมงขึ้นไปมีคำเตือนภาระงานและตัวกรอง OT สูงเกินเป้า
- `UNAPPROVED` = ยังไม่ได้ยืนยันโอที สามารถรับรองรายคนหรือแบบกลุ่มเมื่อสแกนครบและอัตราชัดเจน จากนั้นเป็น `APPROVED` และรวมยอดยืนยันแล้ว ไม่เทียบคำขอเดิมเป็นสำเร็จหรือต่ำกว่าเป้า
- ข้อมูลและ audit เก็บใน PostgreSQL บน Docker volume และแชร์ข้ามเบราว์เซอร์ ไม่อ่านข้อมูลเก่าใน localStorage การ rebuild ไม่ล้างฐานข้อมูล
- มี API และ SQL แล้ว แต่ยังไม่มี login/RBAC และ audit ยังไม่ผูกกับตัวตนผู้ใช้จริง
- ใช้ CSS และ native table พร้อม sticky columns แบ่งหน้าละ 25 คน/รายการ เพื่อลดจำนวน DOM ที่แสดง ไม่ได้ใช้ row virtualization ฟอนต์ Google เป็นทางเลือก มี system-font fallback
- คำนวณเฉพาะข้อมูลในช่วงเวลา/ตัวกรองที่เลือก ทำดัชนี log ตามรหัสเครื่องและกะตามพนักงาน/วัน แล้ว memoize ผลลัพธ์ ลดการค้นหาข้อมูลซ้ำในแต่ละ cell หน้า Audit log ไม่เรียกคำนวณ attendance ส่วน drawer, import modal และ SheetJS โหลดเมื่อจำเป็น
- คอมโพเนนต์หลักอยู่ใน `components/workspace/`; การเชื่อม SQL อยู่ใน `lib/database.ts`, API อยู่ใน `app/api/`, schema อยู่ใน `sql/001-databases.sql`
- ข้อจำกัดการจับคู่ไฟล์จริงและโค้ดที่ยังต้องยืนยันอยู่ใน [ผลวิเคราะห์](docs/examples-analysis.md)
# วันลาและขาดงาน

## หลักฐานการมาทำงาน

ATTENDANCE DETAILS มีส่วนหลักฐานให้แนบรูป JPG/PNG/WebP หรือ PDF สูงสุด 5 MB ต่อไฟล์ / 10 ไฟล์ต่อพนักงานต่อวันเริ่มกะ เลือกแหล่งที่มาจากพนักงานหรือหัวหน้างาน พร้อมชื่อและคำอธิบายเพิ่มเติมได้ การแนบไม่แก้สแกนดิบ ไม่เพิ่มชั่วโมง และไม่ยืนยัน OT อัตโนมัติ

ไฟล์และข้อมูลประกอบเก็บใน `employee_db.attendance_evidence` พร้อม Audit คงอยู่ใน SQL volume หลัง rebuild/restart Docker และไม่หายเมื่อนำเข้า Master หรือสแกนใหม่ ปัจจุบันใช้งานภายในเว็บร่วมกัน ยังไม่มีการตรวจสิทธิ์รายบัญชีหรือยืนยันตัวผู้ให้หลักฐาน

ฐานข้อมูลเดิมให้รัน:
```powershell
Get-Content sql/007-attendance-evidence.sql -Raw | docker compose exec -T database psql -U cj_app -d employee_db -v ON_ERROR_STOP=1
```

## สแกนนิ้วสะสม

ทุกช่องทางนำเข้าเพิ่มสแกนต่อจากข้อมูลเดิมและข้ามรายการซ้ำตามรหัสพนักงาน + วันเวลา + ประเภทสแกน ไม่ลบข้อมูลสแกนเดิม ไม่มีปุ่ม/API ลบสแกน การลบต้องให้ผู้พัฒนาดำเนินการกับฐานข้อมูลโดยตรงเมื่อได้รับคำสั่ง

อ่านข้อมูลทุก batch โดยนับรายการซ้ำเก่าเพียงครั้งเดียว เก็บแถวต้นฉบับและประวัติไฟล์เดิมทั้งหมด `active_punch_batch` เป็นเพียงรหัสการนำเข้าล่าสุด ไม่จำกัดข้อมูลที่แสดงอีกต่อไป โหมดนำเข้า TXT เปิดผลยืนยันใหม่เฉพาะกะที่มีสแกนเพิ่ม และแสดงจำนวนเพิ่มใหม่/ซ้ำ/สะสม

เพิ่ม index สำหรับฐานข้อมูลเดิม (ไม่ลบหรือแก้แถวเดิม):
```powershell
Get-Content sql/006-fingerprint-append.sql -Raw | docker compose exec -T database psql -U cj_app -d fingerprint_db -v ON_ERROR_STOP=1
```

วันหยุดประเพณีองค์กร: ใน Employee calendar → กำหนดวันหยุด → เลือก PH วันหยุดประเพณีองค์กร จะเปิด Popup ให้เลือกวันและยืนยัน บันทึกส่วนกลางใน `company_holidays` ใช้กับทุกพนักงาน/Agency รวมพนักงานที่นำเข้าภายหลัง วันองค์กรมีลำดับสูงกว่าวันลาหรือวันหยุดรายบุคคล ค่ารายบุคคลเดิมเก็บไว้และกลับมาใช้เมื่อยกเลิกวันองค์กร เปิดผลยืนยันที่ได้รับผลกระทบให้ตรวจสอบใหม่ และเก็บ Audit ไม่มีรายการวันหยุดราชการตั้งต้น

ฐานข้อมูลเดิมให้รัน migration ครั้งเดียว:
```powershell
Get-Content sql/005-company-holidays.sql -Raw | docker compose exec -T database psql -U cj_app -d employee_db -v ON_ERROR_STOP=1
```


Employee calendar → กำหนดวันหยุด รองรับ WOP, PL, SL และ AB โดยไม่คิด OT ค่ากะหรือเบี้ยเลี้ยง แม้วันนั้นมีสแกน ระบบเก็บรหัสใน `employee_holidays` และเปิดการยืนยันเดิมให้ตรวจสอบใหม่

ใน Export รายเดือน เลือก “จำนวนวันลาและขาดงาน (WOP / PL / SL / AB)” เพื่อส่งออกจำนวนวันแยกรหัสและรวมตามรอบคำนวณ

ฐานข้อมูลที่สร้างไว้ก่อนหน้าให้รัน migration โดยไม่ต้องลบข้อมูล:
```powershell
Get-Content sql/004-leave-codes.sql -Raw | docker compose exec -T database psql -U cj_app -d employee_db -v ON_ERROR_STOP=1
```
